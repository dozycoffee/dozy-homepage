# 데이터 출처

## 메뉴 카탈로그

- 현재 출처: `public/data/menu.json`. 사용자 요청으로 반영한 메뉴 기획안이며 실제 판매 확정 데이터가 아닙니다.
- 조회: `src/lib/menu-client.ts`의 `fetchMenuCatalog(signal)`이 브라우저에서 GET 요청합니다. 주소 설정은 [configuration.md](configuration.md#환경-변수)가 기준입니다.
- JSON을 import하거나 서버 props로 상품을 주입하지 않습니다. 첫 조회와 수동 재시도 시 `cache: no-store`로 가져오며 자동 폴링은 없습니다.
- 공통 상태와 요청 수명은 `src/lib/use-menu-catalog.ts`에서 관리하며, 메뉴 페이지가 API 클라이언트를 사용합니다. 메인의 광고는 별도 캠페인 설정과 정적 이미지로 표시합니다.
- 타입: `src/content/types.ts`의 `MenuCatalog`, `MenuCategory`, `MenuOptionGroup`, `MenuProduct`.

## 응답 계약

최상위 객체는 다음 네 필드를 가집니다. 배열 순서가 노출 순서입니다.

| 필드 | 형태 |
|---|---|
| `categories` | `{ name: string, children: string[] }[]`. 대분류 이름은 고유하며 소분류 이름은 전체에서 고유 |
| `optionGroups` | `{ name, selectionType: SINGLE 또는 MULTI, required: boolean, options: { optionKey, name, price }[] }[]` |
| `productGroups` | 고유한 그룹 이름 문자열 배열 |
| `products` | 아래 상품 필드의 배열 |

상품 필드:

- `name`: 전체에서 고유한 이름.
- `category`: 선언된 소분류 이름.
- `basePrice`: 옵션을 제외한 원 단위 기본 가격. 0 이상의 안전한 정수, 100원 단위.
- `tracksInventory`: boolean. 음료·푸드는 false, MD는 true. 등록 후 변경하지 않습니다.
- `description`: 60자 이내 한 문장 또는 null.
- `imageUrl`: 현재는 모두 null. 이미지가 없으면 같은 비율의 자리만 표시합니다. 향후 외부 이미지는 `next.config.ts`의 허용 호스트 설정이 함께 필요합니다.
- `tagNames`: 신메뉴·베스트·시즌한정·추천·시그니처 중 최대 2개, 중복 없음.
- `groups`, `optionGroups`: 선언된 이름 참조, 중복 없음.

옵션 그룹 이름은 고유합니다. 옵션은 1개 이상이고 `optionKey`는 그룹 안에서 고유한 영문 대문자와 언더스코어 식별자입니다. 옵션 가격은 0 이상의 안전한 정수이며 필수 그룹의 첫 옵션 가격은 0입니다. MD와 아이스 전용 상품 등에는 상품 성격에 맞는 그룹만 지정합니다.

현재 분류는 음료(커피·논커피·티·에이드·블렌디드), 푸드(베이커리·구움과자·케이크·샌드위치), MD(원두·굿즈)입니다. 사용자 요청으로 새 시그니처 기획 후보 4종에 시그니처 태그를 지정했습니다. 실제 판매 확정 데이터는 아닙니다. 시그니처는 `tagNames`로 구분하며 해당 태그 상품이 있을 때만 화면의 별도 탭으로 표시합니다. 상품 그룹은 시그니처 분류에 사용하지 않으며 현재 `productGroups`와 모든 상품의 `groups`는 비어 있습니다. 탭 동작과 필터 기준은 [메뉴 페이지](pages/menu.md)를 따릅니다. 상품 수 제한이나 가격대는 조회 계약에 강제하지 않습니다.

`parseMenuCatalog`는 응답의 필드 타입, 가격, 고유 이름, 옵션 식별자, 참조를 검증하고 잘못된 응답은 오류로 처리합니다. 대표 카드 동작은 [메인 명세](pages/home.md#동작), 전체 조회·검색은 [메뉴 페이지](pages/menu.md)가 기준입니다.

## API 전환

1. 같은 응답 계약을 제공하는 공개 GET API를 준비합니다.
2. 공개 조회 주소를 환경 변수에 설정하고 재빌드합니다. 다른 도메인이라면 해당 API에서 홈페이지 출처에 대한 CORS 허용이 필요합니다.
3. API 응답 형태가 다르면 `fetchMenuCatalog`에서 이 계약으로 변환합니다. 화면 컴포넌트는 그대로 유지합니다.

현재 인증·주문·결제는 구현하지 않습니다. 비밀 토큰은 브라우저에 넣지 않습니다. 인증이 필요한 API의 연결 방식은 실제 API 선정 시 정합니다.

## 구성 참고

음료군 확대에는 [이디야 공식 음료 메뉴](https://ediya.com/contents/drink.html)의 커피·베버리지·블렌딩 티·블렌디드 음료 구성을 참고했습니다. 상품명·레시피 설명·기획 가격은 도지 기획안이며 타사 판매 데이터 복제가 아닙니다.

## 메뉴 표현

- 국내 공식 메뉴판에서 쓰이는 표기를 참고해 카라멜·라떼·마키아또를 사용합니다. 기준 예시는 [스타벅스 카라멜 마키아또](https://www.starbucks.co.kr/menu/drink_view.do?product_cd=126197)입니다.
- 음료명은 초코라떼·민트초코라떼로 표기합니다 ([빽다방 공식 음료 메뉴](https://paikdabang.com/menu/menu_drink/)). 재료 설명과 디저트명에는 초콜릿을 사용합니다.
- 캐모마일·말차·콜드브루·요거트·프라페·쿠키앤크림은 국내 공식 메뉴에서도 쓰이는 표현이므로 유지합니다. 브랜드별 표기 차이가 있어 단일한 업계 표준이나 사용 빈도 순위로 보지는 않습니다.
- 음료 종류가 이어지는 이름은 콜드브루 라떼·망고 스무디처럼 띄어 읽기 쉽게 표시하고, MD의 머그는 머그컵으로 표시합니다.
- 도지 크림 음료와 블렌드 이름 등 고유 상품명은 도지 기획 이름입니다. 일반 메뉴명의 사용례와 구분합니다.
- 옵션의 표시 이름만 정리하며 `optionKey` 등 식별자는 변경하지 않습니다.

## 태그 지정 기준

상품당 최대 2개를 유지하며 태그가 필요하지 않은 상품은 빈 배열입니다. 시그니처·추천이 함께 붙은 상품은 그 순서로 표시 데이터를 저장합니다.

| 태그 | 지정 기준 | 현재 적용 |
|---|---|---|
| 시그니처 | 본사에서 시그니처 기획 후보로 지정 | 기존 4종 유지 |
| 추천 | 상품군별 대표 선택지와 취향별 입문 메뉴에 대한 기획자의 추천 | 아래 선정 기준 적용 |
| 베스트 | 실제 판매 집계와 본사의 선정 기준 확인 후 지정 | 판매 근거가 없어 비움 |
| 신메뉴 | 실제 출시 일정과 신메뉴 표시 기간 확정 후 지정 | 출시 일정이 없어 비움 |
| 시즌한정 | 실제 시즌 판매 기간과 한정 판매 정책 확정 후 지정 | 상시 기획 목록이므로 비움 |

추천 선정 이유:

- 커피: 아메리카노·카페라떼는 기본 선택, 바닐라라떼는 달콤한 커피, 콜드브루는 다른 추출 방식의 선택지입니다.
- 논커피: 말차라떼·딸기라떼·밀크티는 각각 쌉쌀함·과일의 달콤함·홍차 향을 대표합니다.
- 티: 얼그레이는 홍차, 유자티는 과일티 입문 메뉴로 추천합니다.
- 에이드·블렌디드: 레몬에이드는 산뜻한 탄산, 딸기 요거트 스무디는 새콤달콤한 블렌디드 음료로 추천합니다.
- 푸드: 버터 휘낭시에·소금빵은 커피 페어링, 뉴욕 치즈케이크는 디저트, 햄치즈 샌드위치는 간단한 식사 선택지입니다.
- MD: 데일리 블렌드 원두와 세라믹 머그컵은 집에서 커피를 즐기는 기본 조합입니다.
- 시그니처: 누룽지 크림라떼와 유자말차 에이드는 각각 고소한 커피와 산뜻한 논커피를 대표하는 개발 우선 후보입니다. 두 상품은 시그니처·추천을 함께 지정합니다.

추천은 판매량·품질 검증 결과를 의미하지 않습니다. 맛·원가·운영 방식 검증 후 상품 기획과 함께 다시 평가합니다. 개별 상품의 실제 태그 값은 `public/data/menu.json`이 기준입니다.
